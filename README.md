# AI Engineering Learning Workspace

This is the home for a detailed, six-month applied AI engineering program. The plan uses one flagship product and small experiments to connect concepts to demonstrable engineering work.

## How to navigate

1. **Understand the sequence:** [Program Flow](planning/PROGRAM_FLOW.md)
2. **Understand the syllabus and outcomes:** [Detailed Curriculum](planning/CURRICULUM.md)
3. **See every week’s lesson, build, evidence, and gate:** [24-Week Roadmap](planning/ROADMAP.md)
4. **Follow assigned readings:** [Learning Resources](planning/LEARNING_RESOURCES.md)
5. **See how work is evaluated:** [Assessment Plan](planning/ASSESSMENT_PLAN.md)
6. **Review the proposed product and its boundaries:** [Product Portfolio](planning/PRODUCT_PORTFOLIO.md)
7. **Track actual work:** [Progress](progress/PROGRESS.md), [Learning Log](progress/LEARNING_LOG.md), and [Skill Matrix](progress/SKILL_MATRIX.md)

## Program at a glance

| Month | Focus | Exit artifact |
| --- | --- | --- |
| 1 | Python engineering, APIs, SQL, tests | Reproducible service foundation |
| 2 | Model integration, prompt/context design, evaluation, product discovery | Baseline AI task and agreed MVP brief |
| 3 | Public-source ingestion, search, retrieval, grounded answers | Measured RAG slice with inspectable citations |
| 4 | Quality, observability, reliability, security | Reviewed beta and threat model |
| 5 | Workflow vs agent, MCP, optional distributed systems | Bounded tool experiment or evidence-backed deferral |
| 6 | CI, deployment, operations, portfolio and career review | Reproducible demo and next-quarter plan |

The default pace is 10 focused hours/week for 24 weeks. Stretch the calendar rather than skipping evaluation and reflection. Weekly session flow is documented in `planning/PROGRAM_FLOW.md`.

## Workspace map

- `progress/` — milestones, learning log and evidence-based skill matrix
- `notes/` — durable concept, architecture and debugging notes
- `labs/` — isolated exercises by topic (`python`, `rag`, `mcp`, `agents`)
- `projects/research-intelligence/` — proposed flagship application
- `projects/supporting-projects/` — focused portfolio pieces
- `labs/ai-engineering-labs/` — existing GitHub-backed repository; left intact

## Working rules

- Begin each week with one outcome and finish with evidence.
- Establish a baseline before tuning prompts, adding vector search, or introducing agents.
- Keep data provenance, failure modes, evaluation results and design decisions with the project.
- Use public or explicitly licensed data; never commit employer/customer/private data, credentials, or access tokens.
- Revisit the target-role sample monthly; change elective topics based on repeated requirements.
