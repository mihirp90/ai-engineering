# Topic Learning Tracks — Index

These are **section-wise learning roadmaps**, for example: Java → OOP → collections/generics → JVM → threading/concurrency → Spring Boot. Each track defines dependencies, topics, practice evidence and an exit check.

The 26-week AI/product sequence lives in [ROADMAP.md](../ROADMAP.md). Tracks are not ten simultaneous commitments. Use the three-hour weekly focus block for one selected track, then change at a monthly review based on the product and skill evidence.

## Recommended priority

1. Python engineering — immediate foundation for AI application and evaluation tooling.
2. AI/LLM/RAG — the main capability taught through the core roadmap.
3. Java/JVM/concurrency/Spring — deepen OOP, threading, transaction boundaries and asynchronous patterns.
4. SQL/data/search — essential for ingestion and retrieval.
5. Evaluation/security/observability — non-optional quality foundation.
6. React/TypeScript — product UI after the API/workflow is stable.
7. Distributed systems — Kafka/Flink/Redis only where requirements justify them.
8. MCP/agents — deterministic workflows first, agent autonomy only when evidence supports it.
9. Delivery/DevOps — CI, deployment, operations and recovery.
10. System design/DSA — one hour weekly, alternating between them.

## Completion standard

A topic is not done because a tutorial was watched. Produce one evidence artifact: runnable mini-lab, tests, benchmark, design/decision note, or explanation using a concrete example. Log what failed and what you can now do independently. See [Program Flow](../PROGRAM_FLOW.md) for the weekly hour budget.
